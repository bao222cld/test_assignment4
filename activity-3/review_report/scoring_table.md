## Bảng chấm 4 tiêu chí (PASS / FAIL / WARNING)

| Tiêu chí | PASS / FAIL / WARNING | Nhận xét |
|---|---|---|
| **Maintainability**<br>(Khả năng bảo trì) | **PASS** | **Tên class/method/biến rõ nghĩa:** `LoginPage`, `login()`, `fill_username()`, `get_flash_message()` đều đặt tên đúng chức năng. **Coding Convention:** Tuân thủ chuẩn Python (snake_case cho method/biến, CamelCase cho class). **POM:** Đúng mô hình Page Object Model, file Page chỉ chứa locator và action, assertion nằm ở file test. **Khả năng mở rộng:** Action `login()` giúp dễ tái sử dụng khi bổ sung thêm các test login khác. Tuy nhiên việc khởi tạo browser trong từng test sẽ khó mở rộng nếu dự án lớn (nên chuyển sang fixture của pytest). |
| **Stability**<br>(Độ ổn định) | **WARNING** | **Locator:** PASS. Locator sử dụng `#username`, `#password`, `button[type='submit']`, `#flash` đều khá ổn định. **Wait:** Chưa có explicit wait nào, nhưng Playwright `expect()` đã có auto-wait nên vẫn hoạt động tốt. **Assertion:** Có kiểm tra cả URL và nội dung thông báo nên tương đối đầy đủ theo Expected Result. **Điểm cần lưu ý:** `goto()` không chờ trạng thái tải trang hoàn tất (ví dụ `wait_until="networkidle"` hoặc chờ locator xuất hiện), trong môi trường CI chậm có thể làm tăng nguy cơ flaky. Ngoài ra screenshot được chụp ngay sau assertion mà không đảm bảo flash message đã ổn định hoàn toàn trên UI. |
| **Reusability**<br>(Khả năng tái sử dụng) | **PASS** | Action `login()` đã được tái sử dụng cho cả hai test. Locator được tập trung trong Page Object nên không bị lặp. Logic nhập username/password không bị copy giữa các test. Có thể mở rộng dễ dàng cho các test như Empty Username, Empty Password, Locked User... chỉ cần gọi lại `login()`. |
| **Readability**<br>(Khả năng đọc) | **WARNING** | Code khá dễ đọc, chia nhỏ thành nhiều method ngắn (<20 dòng). Style nhất quán. Tuy nhiên comment chủ yếu mô tả **What** ("Bước 1-3", "Assertion 1") thay vì giải thích **Why** (ví dụ tại sao cần verify URL trước khi verify flash message). Ngoài ra phần comment đầu file khá dài, nếu dùng framework quản lý test (pytest + Allure/Jira) thì có thể chuyển sang docstring hoặc metadata để giảm độ dài file. |
